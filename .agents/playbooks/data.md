# 数据 / 批量处理类任务

对账、日志分析、表格清洗、批量重命名、格式转换。有输入文件，跑脚本，产出结果文件。

## 开工前

1. **看清输入再动手。** 不要假设格式。先看前几行、看有多少行、看编码：

```bash
wc -l 数据.csv
head -3 数据.csv
file -I 数据.csv        # 编码，中文数据经常是 GBK 不是 UTF-8
```

Windows（PowerShell）：

```powershell
(Get-Content 数据.csv | Measure-Object -Line).Lines
Get-Content 数据.csv -TotalCount 3
Get-Content 数据.csv -TotalCount 3 -Encoding utf8    # 乱码就不是 UTF-8，中文数据多半是 GBK
```

2. **问清判定口径。** 「对账」要问清「不一致」怎么定义（金额差多少算差异？空值算不算？时间窗口对不齐怎么办？）。口径不明确会导致产出不可用。

## 执行

### 原始数据只读

```
31-投放日志对账/
├── TASK.md
├── in/          原始数据，只读，绝不修改
├── out/         产出结果
└── run.py       处理脚本
```

- 输入文件复制（不是移动）进 `in/`。原始文件留在原处，处理出错时可从原始文件重新开始。
- 绝不原地修改 `in/` 里的文件。所有产出和中间文件去 `out/`，不要散落在任务目录根。
- `in/` 的文件太大（>50MB）就别复制，在 `TASK.md` 里记下原始路径，脚本直接读。

### 脚本要能重跑

写脚本而不是手敲命令，便于复现。脚本要求：

- 路径写相对路径（`in/xxx.csv`），不写绝对路径，整个目录可搬走。
- 幂等：重复跑结果一样。`out/` 里的文件直接覆盖，不追加。
- 开头三行注释说明：干什么、输入是什么、输出是什么。
- 碰到含手机号、身份证、密钥的数据，产出文件里做脱敏，`TASK.md` 里不贴原值。

```python
# 对账：比对投放日志和结算单的曝光数
# 输入：in/投放日志.csv, in/结算单.xlsx
# 输出：out/差异明细.csv, out/汇总.md
```

### 先小样本验证

数据量大时（>1 万行），先跑前 100 行看结果对不对，再跑全量。

```bash
head -100 in/数据.csv > /tmp/sample.csv
```

```powershell
Get-Content in\数据.csv -TotalCount 100 | Set-Content $env:TEMP\sample.csv -Encoding utf8
```

结果不对时，优先排查口径理解是否有误，其次排查代码逻辑。

### 结果要有汇总

产出不能只有裸数据文件。在 `out/` 里附一份 `汇总.md`，TASK.md 的「结论」填一句话带关键数字：

```markdown
# 对账结果

- 总记录数：投放日志 128,431 条，结算单 128,502 条
- 匹配：128,390 条
- 差异：112 条，明细见 差异明细.csv
- 差异原因分类：
  - 时间窗口跨天导致：89 条
  - 结算单多出的测试数据：23 条
```

数字要能自己对得上（匹配 + 差异 = 总数）。对不上说明脚本有问题。
