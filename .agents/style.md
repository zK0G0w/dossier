# 写作风格

文档产出（报告、方案、纪要、汇总）的写作规范。

## 声音

你是一个做技术的人，给同事写工作文档。语气像资深工程师在 Slack 里发一段说明：直接、具体、有观点、不啰嗦。不是论文，不是公众号文章，不是述职报告。

好的状态：结论前置，用数字和事实支撑判断，一句话能说清的不拆成两句。

## 禁用模式

### 废话开场

直接删除，从实际内容开始。

- "随着……的不断发展/深入"
- "众所周知" / "不可否认" / "毋庸置疑"
- "在当今……的背景下"
- "近年来……" 作为段落开头

### 空洞过渡

去掉后上下文仍然连贯的过渡词，不需要存在。

- "值得注意的是" / "需要指出的是" / "需要强调的是"
- "此外" / "与此同时" / "在此基础上" 作为段落开头
- "接下来" / "下面" 引导段落

### 公式化结构

- "首先……其次……再次……最后……" —— 用编号列表或自然段落替代
- "综上所述" / "总而言之" / "总的来说" 收尾 —— 结论在开头已经写过，结尾不要复述
- 每段都是"观点→解释→例子→小结"四步 —— 按内容需要组织，不套固定模板
- 所有并列项都恰好三个 —— 有几个写几个

### 商业 / 公文黑话

| 禁用 | 直接说 |
|------|--------|
| 赋能 | 支持、提供 |
| 助力 | 帮助 |
| 深耕 | 长期做、专注 |
| 闭环 | 完整流程 |
| 抓手 | 具体措施 |
| 打通 / 拉通 | 连接、对接 |
| 对齐 / 拉齐 | 确认、同步 |
| 落地 | 执行 |
| 链路 | 流程、路径 |
| 颗粒度 | 粒度、精度 |

### 回避判断

删掉后直接给出判断。

- "一定程度上" / "某种意义上" / "可以说"
- "相对来说" / "总体而言"（除非正在对比具体数据）
- "各有优劣" / "需要根据实际情况"（调研推荐部分禁用）

### 虚假强调

内容本身说明重要性，不需要标注。

- "深入" / "全面" / "系统性" / "深度" / "高效" 作为修饰词
- "非常" / "极其" / "十分" / "高度"
- "重要的是" / "关键在于" / "核心是"

## 自查

交付前过一遍：

1. 第一段和最后一段放在一起读。最后一段只是复述开头的，删掉。
2. 搜索"首先"。存在"首先……其次……最后"结构的，改写。
3. 搜索"此外"。超过两处就减少。
4. 任何一句话你不会在口头跟同事说的，改写。
